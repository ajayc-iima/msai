The problem

Retrieval over official PDFs is solved. Governance is not. Unconstrained RAG over sovereign statistics fails in three ways — observed live in MoSPI's StatsDoc pilot (archived transcripts, chats 2472–2480, per evaluation/statsdoc_audit/):

✕Inconsistent figures in one answer. Measured MP MPCE quoted as both 3,158 and 5,589 for urban, and 5,538 vs 4,987 for "All", in a single response (chat 2474).
✕Unguided cross-round arithmetic. ~40% MPCE growth quoted across the HCES 2011-12 → 2023-24 break (paper → 3-visit CAPI) with no caveat.
✕Retrieval poisoning. A poisoned document chunk can override guardrails and flip a verdict.
The thesis. You cannot fix a probabilistic system with more probabilistic prompts. The decision — is this claim allowed? — must come from versioned, deterministic rules, before generation. Models translate; rules judge.

Where it sits

A drop-in governance layer for journalists, fact-checkers, legislative researchers and statistical agencies — a standalone service/CLI and an MCP tool that other agents call as a governance oracle.

  • Service — POST /ask, one JSON endpoint, streaming variant included.
  • MCP tool — vidhi.mcp_server, 4 governance tools, schemas validated.
  • Agent — POST /analyze decomposes a policy question and briefs each claim.
  • Library — vidhi.rules.Firewall imported directly, no service needed.

The rule vocabulary — every refusal is cited

A verdict is never bare prose: it carries a stable reason code.

R_OKverified row matched
R_NO_CURATED_ROWslice not curated → coverage note, no figure
R_NUMERIC_MISMATCHasserted number ≠ the store
R_COMPARABILITY_*survey break → mandatory caveat
R_SCOPE_OUT / R_FORECASTforecast, causal, political → refused
R_PROMPT_INJECTIONinjection refused before any lookup
R_METADATA_*taxonomy check failed
R_LOW_EXTRACTION_CONFextraction confidence too low

Safety-B · freeze before retrieval + figure attestation

The verdict hash is locked before any document is read. A planted "ignore the caveat" chunk changes nothing — the hash is byte-identical with or without poisoning. A second hash binds the number you see to its cell.

frozen_hash = SHA-256(claim ⊕ decision ⊕ sub_code ⊕ reason ⊕ rule_version)
attestation = SHA-256(frozen_hash ⊕ row_id ⊕ value ⊕ unit ⊕ pdf_sha256)

Field-guarded cache · no safe threshold

Danger-pair and paraphrase cosine ranges overlap on both measured embedders, so no similarity threshold is safe. Reuse only on exact critical-field match.

0 collisions across 19 danger pairs · 1708 verified rows (55 touched by the golden set)

Generalised, not hard-coded

The claim translator resolves every state/UT the store carries, in any spelling — “mp”, “up”, “m.p.”, “orissa”, “maharastra” — and answers one state or several at once. A slice the question leaves open is answered with every published cell, each with its own row id: complete, never silently narrowed.

“MPCE in Madhya Pradesh, UP, Maharashtra” → 12 cells · 12 row ids

1 Safety-A“Will unemployment fall in 2027?” pass — no injection signal
2 ScopeREFUSE R_FORECAST — no such round exists

A stage that fires ends the adjudication: stages 4–5 are never reached in either trace. The order is the guarantee.

What stops the three attacks

Prompt injection — Safety-A refuses before any lookup. Poisoned chunk — the hash is already frozen; the chunk changes prose, never the verdict. Cache poisoning — exact critical-field match only.

Honest limits

  • Coverage is the limit, not logic — 1,708 verified rows: the PLFS Highlights battery (11 rounds × usual + CWS × LFPR/WPR/UR × 15+/all-ages × 9 sector-sex cells of both annual reports), the TUS 2024 battery (9 ICATUS divisions × gender/sector/age × participation/per-participant/per-person), and the HCES 2023-24 state + trend columns. State-wise MPCE covers all 36 states/UTs in any spelling; an open slice returns every published cell, never one narrowed figure. Uncovered slices (state-level labour, non-badge rounds) return WARN_NO_DATA + a coverage note, never a guess.
  • Heuristic extraction breaks on exotic phrasing; an LLM translator port exists (VIDHI_USE_LLM=1), unmeasured.
  • No load test yet; eSankhyiki live-API path inherits third-party cert-verification weakness (query path is offline).

What you can inspect

  • Rules, store, claim translator, service, MCP server — vidhi/; 1,708 rows, each sha256-bound to its source PDF.
  • Archived StatsDoc transcripts (chats 2472–2480) + access log + comparison — evaluation/statsdoc_audit/: reproducible, not anecdotal.
  • The four official MoSPI PDFs — data/raw/, committed, so every figure can be re-checked at the page.

Runtime

  • p50 150–190 ms warm, CPU-only — the deterministic adjudication itself is sub-millisecond.
  • Cold start 13–43 s — one-time model load, paid at startup, never per query.
  • $0.00 marginal cost — no API key, no GPU, no network on the query path.
